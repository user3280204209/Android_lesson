### 4.1 适配器 CardAdapter（要求 4b）

**建议截图文件**：`app/src/main/java/cn/edu/sicnu/cardgame/CardAdapter.kt`

核心代码：

```kotlin
class CardAdapter(
    private val onCardClick: (Int) -> Unit
) : RecyclerView.Adapter<CardAdapter.CardViewHolder>() {

    private var cards: List<Card> = emptyList()

    fun submitCards(newCards: List<Card>) {
        cards = newCards
        notifyDataSetChanged()
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): CardViewHolder {
        val binding = ItemCardBinding.inflate(
            LayoutInflater.from(parent.context), parent, false
        )
        return CardViewHolder(binding)
    }

    override fun getItemCount(): Int = cards.size

    override fun onBindViewHolder(holder: CardViewHolder, position: Int) {
        holder.bind(cards[position], position, onCardClick)
    }
}
```

说明文字（可直接使用）：

> `CardAdapter` 从 `RecyclerView.Adapter` 派生，重写了 `onCreateViewHolder`、
> `onBindViewHolder` 和 `getItemCount` 三个方法。`onCreateViewHolder` 负责加载
> `item_card.xml` 并创建 ViewHolder；`onBindViewHolder` 根据牌的三种状态
> （未翻开、已选中、已匹配）设置文字和背景；`getItemCount` 返回牌的总数。
> 适配器通过构造函数接收 `onCardClick` 回调，点击牌面时把位置交给 Activity，
> 由控制器调用模型，适配器本身不修改游戏数据，符合 MVC 的分工。

### 4.3 Model 增加 reset（要求 4c）

**建议截图文件**：`app/src/main/java/cn/edu/sicnu/cardgame/CardMatchingGame.kt`

核心代码：

```kotlin
fun reset() {
    score = 0
    dealCards()
}

private fun dealCards() {
    cards.clear()
    val deck = Deck()
    repeat(count) {
        val card = deck.drawRandomCard()
        if (card != null) {
            cards.add(card)
        }
    }
}
```

说明文字：

> `reset()` 把分数清零并重新创建牌堆、重新发牌，使所有牌恢复为未选中、
> 未匹配状态。“重置游戏”按钮直接调用模型的重置方法，界面再通过适配器刷新。

### 4.4 三张牌匹配逻辑（要求 5）

**建议截图文件**：`Card.kt` 与 `CardMatchingGame.kt`

`Card.match`：

```kotlin
fun match(otherCards: Array<Card>): Int {
    val allCards = listOf(this) + otherCards
    if (allCards.size < 2) {
        return 0
    }

    val allSameRank = allCards.all { it.rank == rank }
    val allSameSuit = allCards.all { it.suit == suit }
    return when {
        allSameRank -> 4
        allSameSuit -> 1
        else -> 0
    }
}
```

`CardMatchingGame.chooseCardAtIndex`：

```kotlin
fun chooseCardAtIndex(index: Int) {
    val card = cardAtIndex(index)
    if (card.isMatched) {
        return
    }

    if (card.isChosen) {
        card.isChosen = false
        return
    }

    card.isChosen = true
    score -= COST_TO_CHOOSE

    val chosenCards = cards.filter { it.isChosen && !it.isMatched }
    if (chosenCards.size == 3) {
        val matchScore = chosenCards[0].match(chosenCards.drop(1).toTypedArray())
        if (matchScore > 0) {
            score += matchScore * MATCH_BONUS
            for (chosenCard in chosenCards) {
                chosenCard.isMatched = true
                chosenCard.isChosen = false
            }
        } else {
            score -= MISMATCH_PENALTY
            for (chosenCard in chosenCards) {
                chosenCard.isChosen = false
            }
        }
    }
}
```

说明文字：

> 实验四是一次选两张牌，本实验改成一次选三张牌。`Card.match` 接收另外两张牌，
> 当三张牌点数全部相同返回 4 分，花色全部相同返回 1 分，否则返回 0 分。
> `chooseCardAtIndex` 每次翻开一张牌先扣 1 分；当已选中的未匹配牌达到 3 张时，
> 三张牌一起参与匹配：成功则三张都标记为已匹配，并按分值加奖励分；失败则扣
> 2 分并取消三张牌的选择。已匹配的牌不能再次选择，已选中的牌再次点击可以撤销。
> 统计规则为：同点数三张得 16 分，同花色三张得 4 分，匹配失败扣 2 分。

## 七、遇到的问题与解决方法（可直接放入报告）

1. **RecyclerView 显示空白**
   - 原因：只设置了 adapter，没有设置 LayoutManager。
   - 解决：在 Activity 中设置 `GridLayoutManager(this, columns)`，再设置 adapter。

2. **按钮设置背景后样式不生效**
   - 原因：最新版 Android Studio 模板主题发生变化。
   - 解决：按实验指导把 `themes.xml` 的父主题改为
     `Theme.MaterialComponents.DayNight.DarkActionBar.Bridge`。

3. **横屏时牌面被底部按钮遮挡**
   - 原因：横屏可用高度较小，仍沿用竖屏的牌面尺寸和列数。
   - 解决：新增 `values-land/dimens.xml`，把横屏牌面高度改为 52dp，并把横屏列数
     改为 15 列 × 2 行，使 30 张牌可以完整显示。

4. **旋转屏幕后游戏重新开始**
   - 说明：横竖屏要求不同牌数（24 张 / 30 张），Activity 重建后按当前方向重新
     发牌是预期行为。后续可以把牌面状态保存到 `onSaveInstanceState` 中进一步优化。

5. **三张牌都不同花色或点数时无法匹配**
   - 说明：游戏规则要求三张牌全部同花色或全部同点数。若剩余牌中已不存在可匹配的
     三张牌，程序会 Toast 提示“没有可以匹配的三张牌了，请重置游戏”，用户可点击
     重置重新发牌。

6. **布局或代码中直接写字符串不符合要求**
   - 解决：所有界面文字集中到 `strings.xml`，布局用 `@string/...` 引用，
     代码用 `getString(R.string....)` 获取。

```bash
git push -u gitee Dev
```

### 9.5 在 Gitee 上保护 Main 分支

1. 打开 Gitee 仓库页面，进入“管理”；
2. 找到“分支设置”/“保护分支设置”；
3. 添加保护分支 `main`；
4. 设置为**不允许直接推送**（或仅管理员可推送），允许合并请求；
5. 保存设置。

截一张图保存为 `screenshots/07_gitee_branches.png`，用于报告。

### 9.6 创建并合并 Pull Request

1. 在 Gitee 仓库页面点击“Pull Requests”→“新建 Pull Request”；
2. 源分支选择 `Dev`，目标分支选择 `main`；
3. 填写标题，例如“实验五 RecyclerView 翻牌游戏应用”；
4. 提交后进行检查/审核，确认无误后点击“合并”；
5. 合并完成后再次查看分支列表，应能看到 `main` 和 `Dev` 两个分支。

截一张 PR 页面或合并结果图保存为 `screenshots/08_gitee_pr.png`，用于报告。
