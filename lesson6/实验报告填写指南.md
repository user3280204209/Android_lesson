### 4.3 对象序列化与文件存储

**建议截图**：`GameStorage.kt`

```kotlin
private fun writeObject(context: Context, fileName: String, data: Any) {
    context.openFileOutput(fileName, Context.MODE_PRIVATE).use { file ->
        ObjectOutputStream(file).use { it.writeObject(data) }
    }
}

private fun readObject(context: Context, fileName: String): Any? {
    return try {
        context.openFileInput(fileName).use { file ->
            ObjectInputStream(file).use { it.readObject() }
        }
    } catch (e: Exception) {
        e.printStackTrace()
        null
    }
}
```

说明：写文件使用 `openFileOutput` 得到文件输出流，再包装为 `ObjectOutputStream`
调用 `writeObject()`；读文件使用 `openFileInput` 得到文件输入流，再包装为
`ObjectInputStream` 调用 `readObject()`。文件保存在应用私有目录，不需要存储权限。

### 4.4 个人信息保存与恢复

**建议截图**：`ProfileFragment.kt`

```kotlin
override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
    super.onViewCreated(view, savedInstanceState)
    profile = GameStorage.loadProfile(requireContext())
        ?: Profile.default(requireContext())
    renderProfile()
}

    super.onPause()
    if (_binding != null) {
        GameStorage.saveProfile(requireContext(), profile)
```

说明：进入个人信息页时先从 `profile.dat` 读取对象，读不到就用默认信息；
页面暂停时把最新信息写回文件。修改信息返回后也会立即保存，因此退出应用后重新打开
仍能恢复。游戏最高分也保存在同一个 `Profile` 对象中。

## 七、遇到的问题与解决方法

1. **游戏对象写入文件时报 `NotSerializableException`**
   - 原因：`Card` 和 `CardMatchingGame` 没有实现 `Serializable`。
   - 解决：两个类都实现 `Serializable`，并添加 `serialVersionUID`，保证序列化版本一致。

2. **切换 Fragment 后游戏进度丢失**
   - 原因：使用 `replace()` 切换 Fragment 时，旧 Fragment 会被销毁，内存中的对象丢失。
   - 解决：在 `onStop()` 中把游戏对象序列化到文件，在 `onViewCreated()` 中读回并恢复。

3. **UI 测试中找不到唯一的底部导航项**
   - 原因：`BottomNavigationView` 的标签同时存在大小两种 TextView，用文字匹配会匹配到两个视图。
   - 解决：测试中改用 `withId(R.id.nav_game_two)` 等 ID 定位。

4. **直接退出应用后数据是否需要保存权限**
   - 说明：使用 `openFileOutput` 写入应用私有目录，不需要申请存储权限；
     文件随应用数据一起保存，卸载应用后才会删除。

> 本实验在实验五的基础上把主界面重构为“一个 MainActivity + 三个 Fragment”。

> 模型和游戏 Fragment 父类，只通过 cardsPerTurn 区分玩法，体现了代码复用。
>
> 程序运行稳定，单元测试 13/13、UI 测试 3/3 全部通过。不足是游戏没有翻牌动画，
> 后续可以增加动画和音效，并把两个游戏的最高分单独记录到排行榜。
